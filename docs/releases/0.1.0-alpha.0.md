# jpm 0.1.0-alpha.0

**Draft release notes — publication has not yet been verified.**

jpm provides a familiar command-line workflow for new Java and Spring Boot applications. Install the CLI through npm; declare Java dependencies in `package.json`; let Maven resolve them and build the application.

## Included

- `create` generates a single-module Spring MVC project using Spring Initializr.
- `install`, `add`, `remove`, and `sync` manage Java declarations and a generated Maven POM with manual-edit protection.
- `dev` recompiles source changes and uses Spring DevTools to restart; `test` and `build` run the Maven Wrapper.
- `list`, `tree`, and `doctor` inspect declarations, resolved dependencies, and the local environment.
- JDK commands discover installations, select a major version through `.jpmrc`, export shell settings, and explicitly install a verified Temurin download.
- Strict TypeScript 7 sources compile to JavaScript for Node 26+. The package includes an MIT license and contributor documentation.

Generated applications do not bundle a CLI archive or depend on an npm installation hook. Teammates install jpm separately.

## Installation after publication

```sh
npm install --global java-npm@alpha
jpm create my-app --java 21 -y
cd my-app
# If needed, explicitly install JDK 21: jpm jdk install 21
jpm install
jpm doctor
jpm dev
```

Requires Node 26+, macOS/Linux, and a suitable JDK. Maven is supplied by the project Wrapper; initial downloads need network access. See the [quick start](../../README.md#quick-start).

## Boundaries

This alpha targets new single-module Spring MVC/Maven projects. Windows, Gradle, arbitrary existing POM import, multi-module builds, custom BOMs/plugins in JSON, exact JDK build pinning, and Java dependency locking are outside its current scope. Commands and configuration may change during alpha.

## Validation

The migration passed 59 automated tests and strict type checking, with archive-install checks on GitHub's Ubuntu and macOS runners. A real macOS application was created, resolved, built, served over HTTP, reloaded after an edit, and stopped cleanly. This is not a claim of equivalent real-Java acceptance testing on every platform. See [the recorded evidence and limitations](../../VALIDATION.md).
